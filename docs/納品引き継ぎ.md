# 納品引き継ぎ

## 1. 納品対象

本リポジトリは X Scout Manager の Flutter Web 管理画面、Firebase 設定、Cloud Functions、Firestore Rules/Indexes、設計ドキュメントを含む。

納品時点の主な機能は以下。

- Firebase Authentication による管理者ログイン
- Firestore による候補、テンプレート、設定、送信キュー、送信履歴、除外対象の管理
- X API 投稿検索による候補抽出
- 候補抽出履歴の表示と抽出解除
- 候補一覧から送信キュー作成
- X API DM送信、手動送信支援、送信済み登録、送信履歴保存
- 除外アカウント管理
- ダッシュボード集計表示
- 成約記録の基盤保持

## 2. 初期MVPでの未完了・追加開発扱い

### API DM送信

API DM送信は1操作1送信の確認式で実装済み。

確認なし一括送信、自動連続送信は実装していない。
X APIでDM送信できることはデバッグアカウントで確認する。
運用上問題がある場合は、手動送信支援と送信済み登録を利用する。

### プロフィール検索

プロフィール検索による候補抽出は初期開発対象外。

現時点では投稿内容のタグ検索を起点とする。
プロフィール文、表示名、username を条件にした抽出は追加開発として扱う。

### 成約記録UI

成約記録UIは初期運用ではメインナビゲーションから非表示。

`/conversions` の直接URLと基盤は将来用に保持している。
成果報酬率・成果報酬額は本システムでは計算しない。

## 3. リポジトリ構成

主なディレクトリは以下。

```text
lib/
  app/                アプリ設定、DI、ルーティング
  core/               共通エラー、UI、認証、シリアライズ
  features/           機能別MVVM
functions/
  src/                Cloud Functions TypeScript実装
  package.json        Functions依存関係、Node.js runtime
docs/                 要件、設計、検証、引き継ぎ資料
tasks/                タスク記録
task-review/          レビュー指摘記録
firebase.json         Firebase設定
firestore.rules       Firestore Security Rules
firestore.indexes.json Firestore Indexes
```

Cloud Functions は `functions/src/index.ts` に処理本体を置かず、機能別ファイルへ分割している。

## 6. Secret管理

X APIの秘密情報はFlutter WebやGitHubへ置かない。

本番Functionsで使用するSecret:

```text
X_BEARER_TOKEN
X_USER_ACCESS_TOKEN
X_USER_REFRESH_TOKEN
X_CLIENT_ID
X_CLIENT_SECRET
```

設定例:

```bash
firebase functions:secrets:set X_BEARER_TOKEN --project x-scout-manager-prod
firebase functions:secrets:set X_USER_ACCESS_TOKEN --project x-scout-manager-prod
firebase functions:secrets:set X_USER_REFRESH_TOKEN --project x-scout-manager-prod
firebase functions:secrets:set X_CLIENT_ID --project x-scout-manager-prod
firebase functions:secrets:set X_CLIENT_SECRET --project x-scout-manager-prod
```

`X_USER_ACCESS_TOKEN` は、送信者となるXアカウントでOAuth認可したアクセストークンを設定する。
`X_USER_REFRESH_TOKEN` は、同じOAuth認可時に発行されたrefresh tokenを設定する。
アクセストークンは期限切れするため、Functions側では401時にrefresh tokenでアクセストークンを再取得してからDM送信を再試行する。
デバッグ確認時はデバッグXアカウントのアクセストークン、本番運用時は本番送信用Xアカウントのアクセストークンへ差し替える。

ローカル検証用の `.env.x-api.local` はGit管理対象外。
リポジトリへ含めるのは `.env.x-api.example` のみ。

## 8. Git引き渡し

remote:

```text
git@github-x-scout-manager:x-scout-manager/x-scout-manager.git
```

納品前に行うこと。

1. `.env.x-api.local` がgit対象外であることを確認する
2. `flutter analyze` を通す
3. `npm --prefix functions run build` を通す
4. `npm --prefix functions run lint` を通す
5. `npm --prefix functions run test` を通す
6. タスク単位でコミットする
7. remoteへpushする
8. GitHubアカウント、Firebase、Google Cloud、X Developer Appの所有・復旧情報をクライアント管理へ移す

## 9. 納品時の動作確認項目

- 管理者ログインできる
- タグ設定を保存できる
- X API候補抽出ができる
- 候補抽出解除ができる
- 候補を選択して送信キューを作成できる
- 送信キューからAPI DM送信できる
- 送信キューから手動送信済み登録できる

- 除外アカウントを復元できる
- ダッシュボードの件数が表示される

## 10. 渡す資料と渡さない資料

渡す資料:

- ソースコード一式
- `docs/` 配下の要件・設計・検証・引き継ぎ資料
- `.env.x-api.example`
- Firebase/GitHub/X Developer Appの管理権限

渡さない資料:

- `.env.x-api.local`
- APIキー、Bearer Token、Client Secret、OAuth Tokenの平文メモ
- 個人アカウントの復旧情報

`tasks/` と `task-review/` は開発経緯の記録として残してよい。
クライアントに内部レビュー記録を見せたくない場合は、納品前に別途整理する。
