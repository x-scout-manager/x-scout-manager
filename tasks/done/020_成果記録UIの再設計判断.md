# 020 成果記録UIの再設計判断

## 現状の動作

成約記録は手動送信支援モードで作成された `send_histories` を起点に登録する。

2026-05-18時点で、成果報酬計算はクライアント側で別途行う方針になった。
そのため、成約記録UIは初期運用のメイン導線から外す。

## 期待する動作

初期運用では成約記録UIをメインナビゲーションに表示しない。

必要になった場合のみ、成果報酬計算ではなく成約記録/成果メモとして再設計する。

## 操作フロー

1. 初期運用ではナビゲーションに成約記録UIを表示しない
2. 成果記録が必要になった時点で、記録項目と運用フローを再確認する
3. 必要なら成約記録/成果メモ画面として再設計する

## UI参考（既存画面）

- `SendHistoryPage`
- `CandidateDetailPage`

## 技術方針

013の `conversions` 基盤は削除せず維持する。

ただし、成果報酬計算や成果報酬管理の画面としては扱わない。
API連携後に追加される `xDmEventId`、投稿ID、APIレスポンス由来の証跡を保存するかは、016 API DM送信の運用確認後に判断する。
