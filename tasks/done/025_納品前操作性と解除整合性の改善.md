# 025 納品前操作性と解除整合性の改善

## 現状の動作

- 候補抽出解除後も、削除済み送信キューの明細がある候補は解除保護で残る場合がある。
- テンプレートは無効化のみで、不要なテンプレートを一覧から消せない。
- 送信キュー詳細から送信キュー一覧へ戻るボタンがない。

## 期待する動作

- 削除済み送信キューの明細は、候補抽出解除の保護対象にしない。
- テンプレートを論理削除でき、一覧から非表示にできる。
- 送信キュー詳細から一覧へ戻れる。

## 操作フロー

1. 不要な送信キューを削除する。
2. 候補抽出履歴から解除する。
3. 送信履歴のない候補は削除または復元され、ダッシュボード候補数へ反映される。
4. テンプレート画面で不要テンプレートを削除する。
5. 送信キュー詳細の「一覧へ戻る」で送信キュー一覧へ戻る。

## UI参考（既存画面）

- `TemplateEditor`
- `SendQueuePage`

## 技術方針

- テンプレート削除は物理削除ではなく `isDeleted = true` の論理削除にする。
- 送信履歴の `templateId` 参照を壊さない。
- 候補抽出解除では、collection groupで見つかったqueue itemの親queueが `deleted` の場合は保護対象から外す。

## 完了条件

- 削除済み送信キューにしか紐づかない候補は抽出解除できる。
- テンプレートを削除すると一覧から非表示になる。
- 送信キュー詳細から一覧へ戻れる。
- `flutter analyze` が通る。
- Functions build/lint/testが通る。

## レビュー指摘

- 候補一覧の解除ボタン押下時、ダッシュボード候補数も0に戻るべきではないか。
- テンプレートは無効化だけではなく削除も必要ではないか。
- 送信キュー詳細からキュー一覧へ戻れない。

## 備考

- 送信履歴がある候補は引き続き抽出解除の対象外にする。
