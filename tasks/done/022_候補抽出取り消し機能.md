# 022 候補抽出取り消し機能

## 現状の動作

`syncCandidates` は抽出結果を即時に `candidates/{xUserId}` へupsertする。
再抽出時は既存候補を更新し、`sourceTags` と `sourcePostIds` は追記マージされる。
誤った条件で抽出した場合、その抽出だけをなかったことにする履歴情報がない。

## 期待する動作

候補抽出をrun単位で記録し、候補一覧画面から直近の抽出を解除できる。
解除時は、そのrunで作成・更新された候補を抽出前の状態へ戻す。
送信済み、送信キュー投入済み、後続抽出で更新済みの候補は解除対象からスキップする。

## 操作フロー

1. 候補一覧画面で候補抽出を実行
2. `candidate_sync_runs/{runId}` と配下changesに抽出差分を保存
3. 候補一覧画面の最近の候補抽出から対象runを確認
4. 解除ボタンを押す
5. 確認ダイアログで解除を確定
6. `revertCandidateSyncRun` が差分に基づき候補を戻す

## UI参考（既存画面）

- `CandidateListPage`

## 技術方針

抽出データは従来通り即時DB保存する。
同時に抽出runと候補ごとの差分を保存し、後からrun単位で巻き戻せるようにする。

`candidate_sync_runs/{runId}` に実行条件、状態、結果を保存する。
`candidate_sync_runs/{runId}/changes/{candidateId}` に `beforeSnapshot` と `afterSnapshot` を保存する。

解除時は以下を守る。

- 新規作成候補は削除する
- 既存更新候補は `beforeSnapshot` に戻す
- 除外キーワード一致で作成された `excluded_accounts` は抽出前状態へ戻す
- `send_histories` が存在する候補はスキップする
- `send_queues/*/items` に存在する候補はスキップする
- `lastSyncRunId` が対象runと異なる候補は後続抽出済みとしてスキップする
