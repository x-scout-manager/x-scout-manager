# 030 最終抽出IDなし候補の再掃除対応と抽出履歴表示改善

## 現状の動作

- 解除済み候補の再掃除で、`lastSyncRunId` がない候補は `最終抽出IDなし` としてスキップされる。
- 候補一覧の「最近の候補抽出」で状態列が狭くなり、「解除済み」が縦表示になる場合がある。

## 期待する動作

- 送信履歴や有効な送信キューに紐づかない古い候補は、`lastSyncRunId` がなくても再掃除できる。
- 状態列は最低限の幅を持ち、状態ラベルを横表示で読める。

## 操作フロー

1. 候補一覧を開く。
2. 「解除済み候補を再掃除」を押す。
3. `最終抽出IDなし` で残っていた候補が削除または復元される。
4. 最近の候補抽出テーブルで「解除済み」が横表示される。

## UI参考（既存画面）

- `lib/features/candidates/view/pages/candidate_list_page.dart`

## 技術方針

- `cleanupRevertedCandidates` で `lastSyncRunId` がない候補のフォールバック判定を追加する。
- `syncRunIds` がある場合は、関連runがすべて解除済みか確認し、最新のchangeから復元/削除する。
- `syncRunIds` もない場合は、送信履歴なし・有効キューなしの安全条件を通過した孤立候補として削除する。
- 抽出履歴テーブルの状態列と操作列に最小幅を設定する。
