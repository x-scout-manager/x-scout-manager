# 028 再掃除対象判定の抽出履歴連鎖対応

## 現状の動作

- 027の再掃除では、候補の `syncRunIds` に含まれる全runが解除済みの場合のみ対象にしている。
- 同じ候補が複数回抽出されると、現在の候補状態に直接関係しない古いrun IDも `syncRunIds` に残る。
- そのため、画面上の抽出履歴を解除済みにしても、候補一覧とダッシュボードの未送信候補数が残る場合がある。

## 期待する動作

- 現在の候補状態を作った `lastSyncRunId` から抽出前状態をたどり、解除済みrunの連鎖だけを戻す。
- 現在状態に関係しない古いrun IDが残っていても、再掃除できる。
- 送信履歴や有効な送信キューに紐づく候補は引き続きスキップする。

## 操作フロー

1. 候補一覧を開く。
2. 「解除済み候補を再掃除」を押す。
3. 確認ダイアログで「再掃除する」を押す。
4. 候補一覧とダッシュボードの未送信候補件数が更新される。

## UI参考（既存画面）

- `lib/features/candidates/view/pages/candidate_list_page.dart`

## 技術方針

- `cleanupRevertedCandidates` の対象判定を修正する。
- `syncRunIds` の全件判定をやめ、`lastSyncRunId` のrunが解除済みかを起点にする。
- `changes/{candidateId}.beforeSnapshot` の `lastSyncRunId` がさらに解除済みrunの場合は連鎖してたどる。
- 最終的に抽出前候補がなければ削除、抽出前候補があれば復元する。
