# 010 手動送信済み登録

## 現状の動作

送信キュー画面で未送信候補とテンプレートを選択し、本文コピー後に手動送信済みとして登録できる。

## 期待する動作

X APIなしで、本文コピー後に手動送信済みとして履歴登録できる。

## 操作フロー

1. 送信キューを開く
2. テンプレートを選ぶ
3. 本文をコピー
4. X上で手動送信
5. 送信済みにする
6. `send_histories` に保存される

## UI参考（既存画面）

- `SendQueuePage`

## 技術方針

`markAsManuallySent` はFirestore transactionで二重登録を防ぐ。

## 実施済み

- `markAsManuallySent` Cloud Functionを追加
- 管理者権限チェックをFunctions側で実施
- queue、queue item、candidate、templateをtransaction内で取得
- queue itemが `pending`、candidateが送信可能、templateが有効であることを再検証
- `send_histories` の同一 `xUserId` 既存履歴を確認し、二重登録を防止
- `send_histories` を `sendMethod = manual` で作成
- candidateを `status = sent`、`isSent = true`、`lastSendHistoryId` 更新
- queue itemを `status = sent`、`templateId`、`sendHistoryId`、`sentAt` 更新
- queueの `completedCount`、`currentIndex`、`status`、`updatedAt` 更新
- 送信キュー画面でqueue/items/templatesをFirestoreから読み込み
- `{{username}}`、`{{displayName}}` の簡易差し込みを実装
- 本文コピーと手動送信済み登録ボタンを追加
- `createSendQueue` のqueue itemに `displayName` を追加
- Functions build、Flutter analyze/test/build webを確認
- `createSendQueue` 更新、`markAsManuallySent` 作成、Hosting deployを確認

## 対象ファイル（推定）

- `functions/src/**`
- `lib/features/send_queue/**`
- `lib/features/histories/**`

## 完了条件

- `sendMethod = manual` の履歴が作成される
- candidate/item/queueが同時更新される
- 同一Xユーザーに二重登録できない

## レビュー指摘

- 既存の送信キュー明細には `displayName` がない可能性があるため、画面側では `username`、`xUserId` にフォールバックする。
- X上で実際にDM送信したかどうかは外部確認できないため、手動送信済み登録は管理者の操作責任で行う。
