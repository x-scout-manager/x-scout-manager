# 027 解除済み抽出由来候補の再掃除

## 現状の動作

- 複数回の候補抽出で同じ候補が更新された場合、古いrunの解除時に `newer_sync_exists` でスキップされることがある。
- その後に新しいrunを解除しても、古いrun側のスキップ候補は再評価されない。
- 結果として、すべての抽出履歴が解除済みでも候補一覧やダッシュボードの未送信候補に候補が残る場合がある。

## 期待する動作

- すべての抽出元runが解除済みの未送信候補を、安全条件付きで再掃除できる。
- 抽出で新規作成された候補は削除する。
- 抽出前から存在した候補は、抽出前の状態へ復元する。
- 送信履歴や有効な送信キューに紐づく候補はスキップする。

## 操作フロー

1. 候補一覧を開く。
2. 「最近の候補抽出」で各runが解除済みになっていることを確認する。
3. 「解除済み候補を再掃除」を押す。
4. 確認ダイアログで「再掃除する」を押す。
5. 候補一覧とダッシュボードの未送信候補件数が更新される。

## UI参考（既存画面）

## 技術方針

- `cleanupRevertedCandidates` Callable Functionを追加する。
- `status == candidate` の候補を対象に、`syncRunIds` と `lastSyncRunId` のrunがすべて `reverted` の場合のみ処理する。
- `send_histories` または削除されていない `send_queues/{queueId}/items` に紐づく候補は保護してスキップする。
- `candidate_sync_runs/{runId}/changes/{candidateId}.beforeSnapshot` を参照し、抽出前候補があれば復元、なければ削除する。
