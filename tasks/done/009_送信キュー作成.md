# 009 送信キュー作成

## 現状の動作

候補一覧で送信可能な候補を選択し、Cloud Functions経由で送信キューを作成できる。

## 期待する動作

候補一覧で選択した候補から送信キューを作成できる。

## 操作フロー

1. 候補一覧で候補をチェック
2. 送信キューに追加
3. Cloud Functions `createSendQueue` を呼ぶ
4. 送信キュー画面へ遷移

## UI参考（既存画面）

- `CandidateListPage`
- `SendQueuePage`

## 技術方針

送信可否判定はCloud Functions側で再検証する。

## 実施済み

- `createSendQueue` Cloud Functionを追加
- 管理者権限チェックをFunctions側で実施
- `candidateIds` の重複排除、空配列、最大100件制限を実装
- 候補の存在、`status == candidate`、送信済み、除外済み、送信履歴、除外アカウントをFunctions側で再検証
- `send_queues/{queueId}` と `send_queues/{queueId}/items/{candidateId}` を作成
- Flutter側の送信キュー作成Repository/UseCaseをFirebase callableへ接続
- 候補一覧に送信可能候補の選択UIと送信キュー作成ボタンを追加
- 送信キュー作成後に送信キュー画面へ遷移
- Firebase callableエラーを画面表示向けにマッピング
- Functions build、Flutter analyze/test/build webを確認
- `createSendQueue` Functions deploy、Hosting deployを確認

## 対象ファイル（推定）

- `functions/src/**`
- `lib/features/candidates/**`
- `lib/features/send_queue/**`

## 完了条件

- 除外済み/送信済み候補はキュー化されない
- キューとitemsが作成される
- Functions build/testが通る

## レビュー指摘

- 候補選択後に一覧がローディング状態へ戻らないよう、VMの状態更新時に `isLoading: false` を明示。
- キュー詳細表示、進行状況表示、送信実行、手動送信済み登録は後続タスクで扱う。

## 備考

最大件数は初期MVPで100件まで。
